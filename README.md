# המתמחים – מעבדת באגים ברשימות מקושרות

אתם המפתחים הבכירים בחברה. השבוע הגיע צוות מתמחים: דני, נועה, מאיה, יוני, עומר וליאת. כל אחד מהם הגיש את אותן שלוש פעולות על רשימות מקושרות. ברוב הפעולות יש באג, אבל לא בכולן.

את הקוד שלהם אתם לא רואים. אתם רואים רק מה הפעולה אמורה לעשות, וזה כל מה שבודק תוכנה אמיתי מקבל.

## מה עושים בכל משימה

1. **כותבים את הפעולה בעצמכם** בקובץ `Lab/Tasks.cs`.
2. **צדים מתמחים.** בקובץ `Lab/MyCases.cs` כותבים **עד 4 מקרי בדיקה**: קלט, ואת התוצאה הנכונה שחישבתם ביד. כל מקרה רץ על כל המתמחים, ומתמחה שמחזיר תוצאה אחרת נתפס. המטרה: להפיל כמה שיותר מתמחים בארבעה מקרים, אז כל מקרה צריך להיות חכם. שימו לב: יש מתמחים שכתבו קוד נכון, ואותם אי אפשר להפיל. (מותר לכתוב יותר מקרים כדי לבדוק את הפעולה שלכם, אבל רק ארבעת הראשונים צדים מתמחים.)
3. **מסבירים.** בקובץ `Answers.md`, לכל מתמחה שתפסתם כותבים משפט אחד: מה הייתה הטעות שלו.

שימו לב: אם התוצאה שכתבתם במקרה בדיקה שגויה, הבודק יגיד לכם ולא יספור את המקרה. אין קיצורי דרך – צריך לחשב ביד.

## איך מתחילים

**אפשרות א – בדפדפן, בלי להתקין כלום.** בדף של המאגר ב-GitHub לוחצים על הכפתור הירוק **Code**, אחר כך **Codespaces**, ואז **Create codespace**. אחרי דקה-שתיים נפתח VS Code בדפדפן, עם הכול מוכן.

**אפשרות ב – במחשב שלכם.** מתקינים פעם אחת:
- [.NET SDK](https://dotnet.microsoft.com/download)
- [VS Code](https://code.visualstudio.com/)
- בתוך VS Code, בלשונית Extensions: התוסף **C# Dev Kit**

ואז ב-VS Code: **Clone Git Repository** ומדביקים את הכתובת של המאגר שלכם.

## איך מריצים את הבודק

פותחים טרמינל (בתפריט: Terminal ← New Terminal) וכותבים:

```
dotnet run --project Lab
```

הבודק מדפיס דוח באנגלית (הטרמינל לא מציג עברית כמו שצריך). לכל משימה תראו:

```
Task 2 - DeleteOdd
  your cases ........ 3 of 4 used, 2 correct
      case #3 (8, 3): the expected result is wrong - trace it again by hand
  your function ..... hidden checks 7/9
      fails on: odd neighbours in the middle; negative numbers
  interns:
    Dani ............ still alive
    Noa ............. CAUGHT by case #2
    ...
  caught ............ 3
```

- `your cases` – כמה מקרים כתבתם, וכמה מהם עם תוצאה נכונה.
- `your function` – הפעולה שלכם נבדקת גם בבדיקות נסתרות. אם היא נכשלת, תראו **איזה סוג** מקרה מפיל אותה, אבל לא את הקלט עצמו. כתבו מקרה כזה בעצמכם וגלו מה קורה. זהירות: הבדיקה שנכשלה אומרת **איפה** הפעולה נשברה, לא **למה**. למשל, נפילה ב-`negative numbers` לא אומרת בהכרח שהבעיה במספרים השליליים. שנו פרט אחד בקלט בכל פעם עד שתמצאו את הסיבה.
- `interns` – מי נתפס ובאיזה מקרה, ומי עדיין חי.

## איך כותבים מקרה בדיקה

```csharp
c.T1("4, 9, 2, 7", 5, 2);          // משימה 1: רשימה, x, התוצאה
c.T2("3, 5, 8, 7, 2", "8, 2");     // משימה 2: רשימה, הרשימה אחרי המחיקה
c.T3("2, 5, 9", 5, 7, "2, 5, 7, 9"); // משימה 3: רשימה, x, y, הרשימה אחרי ההכנסה
```

רשימה ריקה כותבים כך: `""`

**אתגר:** אפשר להפיל את כל מי שאפשר להפיל גם בפחות מארבעה מקרים. מי שמצליח – שיכתוב את זה ב-`Answers.md`.

## הגשה עם git

בכל פעם שהתקדמתם:
1. בלשונית **Source Control** (הסמל עם שלוש הנקודות המחוברות) כותבים הודעה קצרה, למשל `task 2: caught Dani`.
2. לוחצים **Commit**.
3. לוחצים **Sync Changes** (או Push).

ב-GitHub הבודק רץ שוב לבד על כל push, והתוצאה מופיעה בלשונית **Actions**.
